# ZEROSYS Sales Copilot（商談中カンペAI）

Google Meet の「会議タブの音声」と「自分のマイク」を別々に取り込み、日本語で文字起こしし、
本人だけが見る別ウィンドウに「次に言う一言」を短く出すツールです。AI が顧客に話したり送信したりはしません。
正典の仕様は [docs/SPEC.md](docs/SPEC.md)。

## 1. 必要なもの（Windows）

| もの | 入れ方 |
|---|---|
| Windows 10/11 のデスクトップ版 Google Chrome 116 以上 | 普段の Chrome でよい。`chrome://settings/help` でバージョン確認 |
| Node.js 22 LTS（22.13 以上） | https://nodejs.org/ から「LTS」をインストール（または PowerShell で `winget install OpenJS.NodeJS.LTS`） |
| pnpm 10.28.0 | Node に付属の corepack で有効化（下の手順）。バージョンは `package.json` の `packageManager` で固定 |
| ヘッドセット（推奨） | スピーカーだと相手の声を自分のマイクが拾い、「自分側」に混ざることがある |

PowerShell で（初回のみ。権限エラーが出たら「管理者として実行」した PowerShell で）:

```powershell
node -v            # v22.13 以上であること
corepack enable    # pnpm を使えるようにする
pnpm -v            # 10.28.0 と出ること（初回は corepack がダウンロードを確認することがある）
```

## 2. インストール・ビルド・起動

このフォルダ（`sales-copilot`）で:

```powershell
pnpm install          # 依存関係（pnpm-lock.yaml どおり）
pnpm setup:first      # 初回の補助: Node 確認 → .env が無ければ .env.example から作成（既存は上書きしない）→ ビルド → 次の手順を表示
pnpm start            # ローカルサーバーを起動（127.0.0.1:8787）。端末に「ペアリングコード: 123456」が出る
```

| コマンド | 内容 |
|---|---|
| `pnpm start` | 通常起動（サーバー）。止めるのは Ctrl+C |
| `pnpm dev` | 開発起動: サーバーを変更監視で再起動 + 拡張機能を監視ビルド（`apps/extension/dist`）。ペアリングコードはこの端末に出る |
| `pnpm build` | 拡張機能をビルド（`apps/extension/dist`）。サーバーはビルド不要（TypeScript を tsx でそのまま実行） |
| `pnpm test` | 自動テスト（Vitest・実 API は呼ばない） |
| `pnpm typecheck` | 全パッケージの型検査 |
| `pnpm test:e2e` | ブラウザ自動化（Playwright + Chromium）。実サーバー × 実拡張の結合テストと拡張スモーク。必要ならビルドしてから実行。Playwright と Chromium が入った環境が必要（`npm i -g playwright` → `npx playwright install chromium`） |

サーバーの起動時に `ExperimentalWarning: SQLite is an experimental feature` が1行出ますが、動作に影響はありません（Node 22 の node:sqlite）。

## 3. 拡張機能を Chrome に読み込む

1. Chrome で `chrome://extensions` を開く
2. 右上の「デベロッパーモード」を ON
3. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダの `apps/extension/dist` を選ぶ
4. 「ZEROSYS Sales Copilot」が出る。ツールバーのパズル型アイコンからピン留めしておくと押しやすい

ビルドし直したら、`chrome://extensions` でこの拡張の「再読み込み」（丸い矢印）を押します。

## 4. ペアリング（拡張機能とローカルサーバーをつなぐ）

1. `pnpm start` の端末に出ている6桁の「ペアリングコード」を確認（10分有効・1回限り・5回間違えると無効）
2. 拡張機能の「詳細」→「拡張機能のオプション」（設定画面）を開く
3. 「サーバーURL」が `http://127.0.0.1:8787` であることを確認（変えた場合は入力して「保存」）
4. 「ペアリングコード」に6桁を入れて「ペアリング」→「ペアリングしました」と出れば完了

- コードの期限が切れた・使い切った場合は、サーバーを再起動すると新しいコードが出ます。
- **サーバーを再起動するとペアリングは切れます**（トークンはサーバーのメモリにだけ置くため）。再起動後は新しいコードでもう一度ペアリングしてください。トークン自体の期限は 12 時間です。

## 5. API キー（実際の商談で使う場合だけ）

`.env`（`pnpm setup:first` が作成。無ければ `.env.example` をコピー）をメモ帳で開き、次の2つを書いてサーバーを再起動します。

```
DEEPGRAM_API_KEY=（Deepgram のキー）
ANTHROPIC_API_KEY=（Anthropic のキー）
```

- キーはこの PC のサーバーだけが使います。拡張機能・ブラウザ・ログには出しません。`.env` は Git の管理外です。
- キーを書いただけで有料の処理が始まることはありません。外部へ送るのは、本人が LIVE で開始した後だけです。
- 1回の商談の上限（`.env` の `SESSION_MAX_*`）に近づくと警告、達すると新しい外部処理を止めます。

## 6. マイクの許可と最初の音声テスト

1. 設定画面の「マイクを許可してテスト」を押し、Chrome の確認で「許可」→ メーターが声で動くことを確認
   （拡張の裏側の画面は許可の確認を出せないので、最初にここで許可しておく必要があります）
2. 会議タブで拡張アイコンを押すと開く開始前画面で:
   - 「会議側」のメーターが相手の声（または動画の音）で動く。この時点ではこの PC 内で音量を見ているだけで、外部へは送っていません
   - 「マイクをテスト」で「自分」のメーターが動く

## 7. 実際の Meet での開始と終了

**ふだんはこれだけ: Meet参加→ポップアップの接続を1回押す**

1. ブラウザ版の Google Meet の会議（`https://meet.google.com/xxx-xxxx-xxx`）に参加する
2. 会議の画面の右上に「ZEROSYS カンペ」のポップアップが出る →「**接続**」を 1 回押す
   - 押すのは、相手に説明・同意を得ている場合だけ（この 1 回が、開始前画面の「②商談相手への説明・同意」の確認の代わりです）
   - Chrome の追加の確認は出ません（Meet に許可済みのマイクと、Meet が受信している相手の音声を、そのページの中で使うため）
3. カンペウィンドウが開き、確認画面なしで始まる
   - モード: 前回使ったモード。サーバーに Deepgram / Anthropic のキーがあれば LIVE、無ければ OFFLINE テスト
   - 商談目的: 会議名が入る。商談中にカンペ画面上部の「変更」で直せます
   - 自動で始められないとき（ペアリング切れ・サーバー停止など）は、理由と直し方が開始前画面の一番上に出ます
4. 接続しないときは「**拒否**」（または ×）。その会議では何も取得せず、同じタブでは再読み込みしても出ません
5. 商談中: 【今の一手】【次に言う一言】【今は言わない】を見る。ボタンとキー:
   切り返し(R) / 次に聞く(Q) / 次の約束(N) / 表示固定(P) / 役立った(G) / ずれた(B) / 自分の音声取得OFF(M) / 解析一時停止(S) / 終了(E)、文字サイズ(+/-)、明暗(D)
6. 終わったら「終了」→（任意）「振り返りをこのPCのファイルへ出力する」→「終了する」。カンペウィンドウを閉じても、Meet のタブを閉じても終了します

ポップアップを拒否した後や、うまく出ないときの代わりの方法（従来の手順）:
1. **その会議タブで**拡張アイコンを押す → 開始前画面が開く（以後ほかのタブへ移っても対象は変わりません）
2. 商談目的（必須）・顧客名（任意）・今回使う承認済み条件を選び、「LIVE」を選ぶ
3. ①ブラウザのマイク許可 と ②商談相手への説明・同意（または社内承認）を別々に確認してチェック
4. 「開始の確認へ」→ 送信先（Deepgram・Anthropic）を確認して「開始する」

注意:
- **Meet でミュートしても、このアプリの自分の音声取得は止まりません。** 止めたいときは「自分の音声取得OFF」を押してください。
- 会議タブを閉じる・共有や権限を取り消すと、取得は止まります（別のタブへ勝手に切り替えません）。

## 8. 画面共有の注意

Meet で共有するときは「**タブ**」を選び、資料のタブだけを共有してください。
「画面全体」や「ウィンドウ」で共有すると、カンペのウィンドウが相手に映る可能性があります（このアプリは「常に最前面」や「共有に映らない」を保証しません）。

## 9. API キーなしで試す（OFFLINE テスト）

キーが無くても、架空の会話を再生して一連の動きを確認できます。外部へは何も送りません。

1. `pnpm start` → ペアリング（4章）→ マイク許可（6章）
2. 普通の Web ページのタブ（Meet でなくてよい）で拡張アイコンを押す
3. 商談目的に何か入れ、「OFFLINEテスト」を選ぶ → 「再生する架空会話」を選ぶ（約1〜2分の3種類）
4. ②の確認（と、自分の音声を取得する場合は①）にチェック →「開始の確認へ」→「開始する」
5. 文字起こし履歴が増え、カンペが出ることを確認。ボタン（切り返し・次に聞く・次の約束）、一時停止、終了も試せます

- OFFLINE の助言は**ルールベース（AI ではありません）**で、カードの理由に `[OFFLINE規則]` と付きます。
- `.env` で `OFFLINE_USE_ANTHROPIC=1` かつ `ANTHROPIC_API_KEY` がある場合だけ、開始画面で「助言生成に Anthropic を使う」を選べます（架空会話の文字が外部へ送られ、使用量が発生します。既定は OFF）。
- 再生速度は `.env` の `OFFLINE_REPLAY_SPEED`（1 = 実時間）。

## 10. どのデータがどこへ送られるか

| データ | 送り先 | いつ |
|---|---|---|
| 会議タブの音声・自分のマイク音声（16kHz PCM） | この PC のローカルサーバー（127.0.0.1）→ **Deepgram**（文字起こし） | LIVE で開始した後だけ。一時停止・終了・自分の音声OFF で止まる |
| 直近 60〜120 秒の確定した文字起こし・構造化メモ・今回使う承認済み条件・商談目的 | ローカルサーバー → **Anthropic（Claude）**（助言生成） | LIVE で、助言が必要な発言・ボタンのときだけ（毎回全文は送らない） |
| 開始画面で入力した顧客名 | どこにも送らない（ローカルの表示と、本人が選んだ場合の出力ファイルだけ）。ただし会話の中で話された名前は文字起こしの一部として上の2社へ送られる | — |
| OFFLINE テスト | 外部送信なし（Anthropic を明示的に選んだ場合だけ架空会話を Anthropic へ） | — |
| 評価したカードの文面・商談目的・今のルール（改善案づくり） | ローカルサーバー → **Anthropic（Claude）** | 設定画面で「改善案を作る」→ 目安の費用を見て「この内容で作る」を押したときだけ |

外部の事業者（Deepgram・Anthropic）側でのデータの保持は、各社の規約・契約によります。「外部に一切保存されない」とは言えません。

## 11. 保存されるものと削除方法

| もの | 既定 | 場所 |
|---|---|---|
| 音声 | **保存しない** | — |
| 会話の文字・カンペ | **メモリのみ**。終了後 10 分（`SESSION_RETENTION_MS`）で消える | サーバーのメモリ |
| 振り返りファイル（JSON + Markdown） | 終了時に本人が「出力する」を選んだときだけ | `exports/` |
| 承認済み条件とその履歴、使った条件の版 | 保存する | `data/sales-copilot.sqlite` |
| 「役立った／ずれた」の評価と、評価したカードの文面・商談目的（会話の文字起こし・顧客名は保存しない） | 保存する（文面は設定画面で OFF にできる） | `data/sales-copilot.sqlite` |
| 承認した営業補正ルールとその履歴・版 | 保存する | `data/sales-copilot.sqlite` |
| ペアリングのトークン | 拡張機能の保存領域（この拡張だけが読める）。サーバー側はメモリのみ | Chrome |

学習の記録だけを消すときは、設定画面の「学習データを全部消す」を押します（承認済みのルールは残り、個別に削除できます）。
削除方法: サーバーを止めて、このフォルダの `exports/`（振り返りファイル）と `data/`（承認済み条件など）を削除します。
拡張機能側は設定画面の「解除」でトークンを消せます（拡張機能を削除しても消えます）。
`data/` `exports/` `.env` `*.sqlite` `dist` は Git の管理外です。

## 11-2. 学習（承認制）

- 商談中にカードの「役立った」「ずれた」を押すと、そのカードの文面と商談目的だけが保存されます（会話の文字起こし・顧客名は保存しません）。
- 設定画面の「学習（承認制）」で「改善案を作る」を押すと、AI が評価から改善ルールの案を最大5件出します（費用の目安を見てから実行）。
- 案は「承認」「却下」「編集して承認」で選びます。承認したルールだけが**次の商談から**カンペ作りに使われ、勝手には変わりません。
- ルールは止める・削除ができ、変更の履歴と、版ごとの「役立った」率（10件未満は「データ不足」）が見られます。
- 金額・期間などの条件はルールにできません。それは「商談条件（承認済み情報）」に登録します。

## 12. 対応環境と既知の制約

- 対象: Windows のデスクトップ版 Chrome（116 以上）+ ブラウザ版 Google Meet。Zoom / Teams のアプリ・スマホ・対面会議は対象外。
- 自動テストは Linux 上の Chromium 153（Chrome for Testing・headless）で実施。**Windows の Chrome での動作は未確認**（下の表）。
- Meet のポップアップの「接続」は、Meet のページの中で相手の音声（Meet が受信している音声）と Meet に許可済みのマイクを使います。
  Google が Meet の作りを変えると取れなくなる可能性があります。その場合は拡張アイコン（タブの音声取得）で開始してください。
- 拡張アイコンからの会議タブの音声取得は、自動化のテストでは再現できない（アイコンを押す操作が必要）。
- この拡張は `https://meet.google.com/` のページにだけスクリプトを入れます（ほかのサイトには入りません）。
- 「会議側」は相手が複数でも1つの系統です。声から名前・役職は推測しません。
- サーバー再起動でペアリングが切れます（4章）。
- Windows では `data/` `exports/` のファイル権限（0600）の指定が効きません。PC のアカウント管理で保護してください。
- カンペウィンドウの「常に最前面」は保証しません。
- 遅延の目標（相手の発話終了 → 表示 p50 3 秒以内 / p95 5 秒以内）は開発目標で、保証ではありません。実 API では未計測です。

## 13. 遅延の計測と使用量・費用の前提

- 遅延: サーバーが「発話終了推定 → STT 確定 → 生成要求 → 検証完了 → 送信 → 画面の表示報告」を同じ時計で記録します。
  実行中は `GET /sessions/active/latency`、終了後は振り返り（10分以内）または出力ファイルの `latency` で見られます。詳細は [docs/latency.md](docs/latency.md)。
- 使用量: 文字起こしは自分側・会議側の**両方の秒数を合計**、助言生成は API が返した実際のトークン数と呼び出し回数で数えます。
- 費用: **既定では金額を出しません（使用量のみ）。** 価格表（`.env` の `PRICE_*`）を出典と確認日つきで設定した場合だけ、その通貨1つで概算します。
- 上限（`.env.example` の値）: 文字起こし 7200 秒（両系統の合計なので、2系統で約60分）、助言 400 回、入力 200 万トークン、出力 20 万トークン。80% で警告、100% で新しい外部処理を止めます。60 分を超える商談では上限を見直してください。

## 15. フォルダ構成

| ディレクトリ | 責務 |
|---|---|
| `apps/extension` | Chrome MV3 拡張（音声2系統取得・Meet の接続ポップアップ・カンペウィンドウ・設定画面） |
| `apps/server` | ローカル Fastify + WebSocket サーバー（127.0.0.1 のみ） |
| `packages/contracts` | 共有 Zod スキーマ・型（WS メッセージ・音声フレーム・HTTP 応答） |
| `packages/domain` | 文字起こし統合・会話状態・助言スケジューラー・ライフサイクル・使用量 |
| `packages/coaching` | プロンプト・助言エンジン・表示前検証・OFFLINE 用ルールベース |
| `packages/providers` | Deepgram / Claude アダプターと偽物 |
| `packages/test-fixtures` | 架空会話・回帰フィクスチャ・OFFLINE 再生台本 |
| `scripts` | `setup.mjs`（初回）・`dev.mjs`（開発起動）・`e2e.mjs` / `e2e-integration.mjs`（ブラウザ自動化） |
| `docs` | 仕様と設計資料 |

パッケージは TypeScript ソースのまま `exports` で公開し（`./src/index.ts`）、サーバーは tsx、拡張は Vite がそのまま解決します（`moduleResolution: Bundler`）。
