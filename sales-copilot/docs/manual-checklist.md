# 実機チェックリスト（SPEC §16-2・人間が実施）

ブラウザ自動化（Vitest / Playwright）の合格と、実際の Meet 会議での動作は別物として扱う。
下の項目は**まだ実施していない**（2026-11-16 時点・未確認。A は 2026-11-17 追加・未確認）。実施したら日付・Chrome バージョン・結果を書く。

準備: Windows / Chrome 116+ / ヘッドセット推奨。サーバーを起動し、拡張を `apps/extension/dist` から読み込み、
設定画面でペアリングと「マイクを許可してテスト」を済ませる。相手役は社内の別アカウント（架空の会話で行う）。

- [ ] **0. マイク許可の流れ**
  1. 拡張を入れ直した直後の状態で設定画面を開き「マイクを許可してテスト」→ Chrome の許可ダイアログで「許可」。
  2. メーターが動き、マイク名が表示される。
  3. copilot の開始前画面で「ブラウザの許可: 許可済み」と出る。許可を取り消して開始した場合、自分側が「権限なし」と直し方付きで出る。

- [ ] **A. Meet参加→ポップアップの接続を1回押す（ワンタップ接続）** ← 最初に確認する
  1. Meet の会議に参加 → 会議画面の右上に「ZEROSYS カンペ」ポップアップ（接続／拒否・同意の一文）が出る。
     参加前の待機画面や、会議コードの無い Meet トップでは出ないこと。
  2. 「接続」を 1 回だけ押す → Chrome の確認ダイアログが追加で出ないこと。カンペウィンドウが開き、開始前画面を経ずに商談画面になる。
  3. 状態バーで 会議側=取得中・自分側=取得中。モードは前回のモード（キー設定済みなら LIVE）。商談目的に会議名が出る（「変更」で直せる）。
  4. **相手の発言と自分の発言が、両方とも文字起こし履歴に「会議側」「自分」として別々に出ること**（1 回のタップだけで）。
  5. 相手の声が普段どおり聞こえる（無音・二重にならない）。相手側に自分の声がエコー・二重で届かない。
  6. 相手が後から参加・退出しても会議側の文字起こしが続く。
  7. 解析一時停止 → 両方の文字起こしが止まり、Windows のマイク使用中表示がこのアプリの分だけ消える（Meet 自身の分は残る）。再開で戻る。
  8. 終了 → 同じ会議ではポップアップが勝手に出直さない。Meet のタブを閉じる／再読み込みすると、カンペも終了する。
  9. 別の会議で「拒否」→ 何も開かない。そのタブで再読み込みしても、同じ会議では出ない。
  10. 記録: 日付・Chrome のバージョン・Meet の表示言語・結果（ポップアップが出なかった／会議側が無音などは、その画面の状態も）。

- [ ] **1. Meet で二系統入力（拡張アイコンからの代わりの方法）**
  1. Meet に参加し（ポップアップは「拒否」）、その会議タブで拡張アイコンを押す → copilot ウィンドウが開く。
  2. 開始前画面の「会議側」メーターが相手の声で動く（この時点では外部へ送っていない表示）。
  3. 自分のマイクをテストし「自分」メーターが動く。
  4. OFFLINE または LIVE で開始し、状態バーで 会議側=取得中、自分側=取得中。文字起こし履歴に「会議側」「自分」が別々に出る。
  5. copilot を開いた後に別タブへ移っても、取得対象が会議タブのまま変わらない。

- [ ] **2. 会議音声が聞こえる・ハウリングしない**
  1. 取得開始後も相手の声が普段どおり聞こえる（無音にならない・二重に聞こえない）。
  2. 相手側に自分の声がエコー・二重で届いていない（自分のマイクはスピーカーにも会議にも戻していない）。
  3. スピーカー使用時も確認（ヘッドセット推奨の理由になるか記録）。

- [ ] **3. Meet のミュートと「自分の音声取得」の違い**
  1. Meet でミュートにして話す → このアプリの自分側は取得中のまま（文字起こしに自分の発言が出る）ことを確認。
  2. 「自分の音声取得OFF」（キー M）→ 自分側が「取得OFF」、自分の発言が文字起こしに出なくなる、Windows のマイク使用中表示が消える。
  3. 「自分の音声取得ON」で再開できる。

- [ ] **4. 実 API 経由の助言（LIVE）**
  1. サーバーに Deepgram / Anthropic のキーを設定し、使用上限を小さくして LIVE で開始（送信先の最終確認が出る）。
  2. 相手役が価格や導入時期を質問 → 数秒以内に【次に言う一言】が出る。未承認の金額を言い切らない。
  3. 「切り返し」「次に聞く」「次の約束」が動く。使用量表示が増える。

- [ ] **5. 話題転換で古い助言が外れる**
  1. 助言が出た後に相手が別の話題へ移る → 古いカードが「参考」または「無効」ラベルになる。
  2. 表示固定（キー P）中に新しいカードが来る → 固定カードは残り「参考」＋「新しいカードがあります」。解除で新カードへ。

- [ ] **6. 終了・権限取消・タブ終了で停止**
  1. 「終了」→ 確認 → 終了画面。タブのマイク/共有表示が消え、相手の声が通常どおり聞こえる。
  2. 再度開始し、copilot ウィンドウを × で閉じる → サーバー側で session.end、取得表示が消える。
  3. 再度開始し、会議タブを閉じる → copilot に「会議タブが閉じられたため終了」。
  4. 再度開始し、Chrome のタブ共有／マイク権限を取り消す → 停止または自分側「権限なし」と直し方が出る。
  5. いずれも停止後にサーバーへ音声が届き続けない（サーバーログの受信フレーム数が増えない）。

- [ ] **7. タブ共有に映り込まない**
  1. Meet で「タブを共有」で資料タブだけを共有 → 相手側にカンペが映らない。
  2. 参考: 全画面共有では copilot ウィンドウが映る可能性があることを確認し、開始前画面の注意文どおりであることを確認。

- [ ] **8. 60 分連続稼働**
  1. LIVE（上限を設定）または OFFLINE で 60 分連続稼働。
  2. 途中で音声欠落表示が出ないか、メモリ使用量（chrome://task-manager の拡張/オフスクリーン）が増え続けないか、遅延表示を記録。
  3. 60 分後に終了し、全て止まることを確認。

- [ ] **9. 画面共有・切替で終わらない（2026-11-17 実商談の再確認・最優先）**
  1. 「接続」で LIVE 開始（開始直後に「LIVE（本物の会話を解析中）」と大きく出る。OFFLINE の表示が出たら不合格）。
  2. Meet で「画面を共有」→ 資料のタブ／ウィンドウ／全画面それぞれで共有開始・停止を 2 回ずつ → カンペは LIVE のまま、相手の発言の文字起こしが続く。
  3. 別のタブ・別のアプリ（Excel 等）に切り替えて 10 分以上そのまま（カンペ画面が隠れた状態）→ 戻っても LIVE のまま。
  4. カンペ画面を最小化して 10 分 → 戻しても LIVE のまま。
  5. サーバーを止めて 10 秒後に起動し直す（`pnpm start`）→ カンペに「再接続中（商談は続いています）」→ 戻ると同じ商談で続く。
     ※ サーバーの再起動ではメモリ上の商談が消えるため、この場合は「接続が切れたまま再接続できなかった」で終わるのが正しい動作（再接続できるのは一時的な切断のみ）。
  6. 通話から退出 → 10 秒ほどで終了画面「通話から退出したため終了しました」。サーバーログの `session ended` に `endReason":"call_left"`。
  7. 途中で終わってしまった場合は、終了画面の文言とサーバーログの `endReason` を記録する（原因の切り分けに使う）。

- [ ] **10. 商談目的なしで開始・ペアリング期限なし**
  1. 拡張アイコンからの開始前画面で、商談目的を空欄のまま開始できる（会議名、無ければ「商談」が入る）。
  2. 設定画面の「ペアリング: 済み（期限なし・「解除」を押すまで有効）」。「解除」で切れ、`pnpm pair` で再ペアリングできる。
