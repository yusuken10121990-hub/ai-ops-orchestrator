# セキュリティ設計（ローカルサーバー: apps/server）

SPEC §14 の実装内容と、それを確認する自動テスト。

## 待受

- `HOST`（既定 `127.0.0.1`）にだけ bind する。`0.0.0.0` などループバック以外は `ALLOW_NON_LOOPBACK=1` を明示しない限り
  起動を拒否する（`assertBindAllowed`）。
- 起動時に外部 API へ接続しない。STT はセッション開始後に最初の音声が届いた時、LLM は契機・ボタンがあった時だけ使う。

## ペアリングとトークン

- 起動時に 6 桁の一度限りのペアリングコードを発行し、**端末（TTY）にだけ**表示する（ログには出さない。TTY でない場合は表示しない）。
  `pnpm start` / `pnpm dev` は端末をそのまま渡すので表示される。自動起動（端末なし）では `pnpm pair` で出す（下記）。
- 自動テスト専用の固定コード `PAIRING_CODE_FOR_TEST` は **`NODE_ENV=test` のときだけ**受け付ける。それ以外の環境で設定されていると
  サーバーは起動を拒否する（`config.ts` の `pairingCodeForTest`、`units.test.ts` で確認）。コード自体はログに出さない。
- `POST /pair`（`{ pairingCode, extensionId, clientName }`）: `Origin: chrome-extension://<extensionId>` と body の ID が一致すること。
  `ALLOWED_EXTENSION_ID` を設定した場合はその ID に限定。コードは単回使用・10 分有効（`PAIRING_CODE_TTL_MS`）・
  試行 5 回（`PAIRING_MAX_ATTEMPTS`）で失効（以後はサーバー再起動で新コード）。
- 成功時にランダム 32byte（base64url）のセッショントークンを返す。スコープ `session` / `settings`、拡張機能 ID に束縛。
  **既定は期限なし**（`SESSION_TOKEN_TTL_DAYS` 未設定 または `0`。実体は約 100 年の期限。2026-11-17 オーナー指示「永久にしておいてよ」）。
  `1〜400` を設定するとその日数。どちらも**検証に成功するたびに now + 期限へ延長**（スライド。ディスクへの保存は 1 時間に 1 回まで）。
  旧設定 `SESSION_TOKEN_TTL_MS`（以前の `.env.example` は 12 時間）は無視し、起動時に警告だけ出す。
- `GET /auth/check`（Bearer 必須）: 有効なら最新の期限を返す。拡張機能は Meet の「接続」前と設定画面でこれを呼び、保存している期限を合わせる。
  401 なら「ペアリングが切れました → 設定画面で再ペアリング」を出す。`POST /auth/revoke`: 設定画面の「解除」。そのトークンを失効させ記録からも消す。

## ペアリング記録の永続化（脅威モデル）

再起動のたびの再ペアリングをなくすため、トークンの記録を本人用フォルダに保存する。

- 場所: `USER_DATA_DIR`（既定 Windows `%LOCALAPPDATA%\ZEROSYS-SalesCopilot`、macOS `~/Library/Application Support/ZEROSYS-SalesCopilot`、
  その他 `$XDG_STATE_HOME`（`~/.local/state`）配下）の `tokens.json`（`TOKEN_STORE_FILE` で変更可）。
- 中身: トークンの **SHA-256 ハッシュ（hex）**・拡張機能 ID・スコープ・発行/期限/最終使用時刻のみ。**平文トークンは保存しない。**
  ファイルを盗まれてもハッシュから 256bit のトークンは復元できず、なりすましには使えない。
- 書き込み: 同じフォルダの一時ファイル（0600 で作成）に書いて fsync → rename（原子的。途中で落ちても壊れた JSON を残さない）。
  フォルダ 0700 / ファイル 0600（POSIX）。Windows では chmod はほぼ効かないが、`%LOCALAPPDATA%` は既定でそのユーザー（と管理者・SYSTEM）だけが
  アクセスできる ACL。壊れたファイルは使わずに起動し（再ペアリングが必要になる）、次の保存で置き換える。
- 件数上限 20（再ペアリングのたびに増え続けない。最後に使ったのが古い順に消す）。期限切れは読み込み時・検証時に消す。
- 残る危険と対策:
  - **長寿命化**: 拡張機能の保存領域（`chrome.storage.local`）からトークンが盗まれると、使われ続ける限り有効。
    ただしトークンは拡張機能 ID・127.0.0.1 の Host・Origin に束縛され、同じ PC 上でしか使えない。漏えいが疑われたら「解除」か
    `tokens.json` の削除（サーバー停止中）で全失効。**既定では時間切れによる失効が無い**ので、失効させる手段は
    「解除」・`tokens.json` の削除・（期限を付けたい場合）`SESSION_TOKEN_TTL_DAYS` の設定の 3 つ。PC を手放す・共有する前には必ず「解除」する。
    期限なしにしても、束縛（拡張機能 ID・127.0.0.1・Origin）と保存方式（ハッシュのみ）は変わらないため、別 PC・別ユーザー・Web ページからの
    悪用の難しさは変わらない。増えるのは「同じ PC で盗まれたトークンが使われ続けうる期間」だけ。
  - **同じ PC の同じユーザーで動く悪意あるプログラム**は、もともと拡張機能のデータもこのファイルも読める（OS のユーザー境界の内側）。
    この設計はその境界を前提にしており、別ユーザー・別 PC・Web ページからの悪用を防ぐことを目的にする。

## pnpm pair（端末なしでペアリングコードを出す）

自動起動のサーバーは TTY を持たないため、コードを出す経路を別に用意する。最も単純で安全な方式として次を選んだ。

- サーバーは起動ごとにランダム 32byte の秘密を作り、本人用フォルダの `local-admin.json`（0600・原子的書き込み）に
  `{ host, port, pid, secret }` を置く。終了時に消す（別の起動が上書きしていれば消さない）。
- `pnpm pair`（`scripts/pair.mjs`）はそのファイルを読み、`POST http://127.0.0.1:<port>/local/pairing-code` に
  ヘッダー `x-zerosys-local-secret` を付けて送る。サーバーは SHA-256 同士を timingSafeEqual で比べ、一致すれば新しいコード（10 分・1 回限り・
  試行上限あり。通常のペアリングと同じ）を発行して返す。コードはその端末に表示するだけで、ログ・ファイルには書かない。
- **`Origin` 付きの要求は拒否（403）**: Web ページや拡張機能のページからは、秘密を知っていてもこの経路を使えない。Host 検査（421）も通常どおり。
- 秘密が無い構成（テスト等）ではこのルートは 404。
- 選ばなかった案: 「設定画面にコードを表示」は、拡張機能がローカルの秘密ファイルを読めないため、結局ブラウザから届く何かを信用する必要があり、
  Web ページからの悪用面が増える。`pnpm pair` なら「この PC のこのユーザーのファイルを読める人」だけに限定できる。

- HTTP: `Authorization: Bearer <token>`。WebSocket: 接続後最初の `hello` メッセージの `token`（5 秒以内。来なければ 4408 で切断、
  不正なら 4401）。**URL クエリに token / access_token / key 等が付いたリクエストは 400 で拒否**（受け付けない）。

## Origin / Host 検査（CORS だけに頼らない）

- 全 HTTP リクエストと WebSocket アップグレードで `Host` が `127.0.0.1:<PORT>` / `localhost:<PORT>` / `[::1]:<PORT>` 以外なら 421
  （DNS リバインディング対策）。
- `/health` 以外は、`Origin` があれば「ペアリング済み（または環境変数で許可）の `chrome-extension://<id>`」であること。違えば 403。
  トークンも同じ拡張機能 ID のものでなければ 401。
- **`Origin` ヘッダーが無い HTTP 要求**: Chrome は host_permissions を持つ拡張ページからの GET に `Origin` を付けない
  （実ブラウザの結合テスト `scripts/e2e-integration.mjs` で確認。モックでは見つからなかった不具合）。この場合は Bearer トークンの検査
  （期限・スコープ・発行先の拡張がペアリング済み）だけで判定する。Web ページが `Authorization` ヘッダーを付けると必ず CORS
  （`Origin` 付き）になるため、ブラウザ上の第三者ページはこの経路を使えない。
- **WebSocket アップグレードは `Origin` 必須**（ブラウザは常に付ける）。無い・違う場合は 403。
- `/health` は認証なし・最小（`{ ok, version }`）。

## ログ

- pino。会話本文・顧客名・商談目的・カンペ文・トークン・API キー・ペアリングコードをログに渡さない（ID・件数・理由コードのみ）。
- 多層防御として `text` / `token` / `apiKey` / `customerName` / `purpose` / `say` / `headline` 等のキーを redact。
- リクエストログ（URL・ヘッダー）は出さない。エラーはスタック・メッセージを出さず name / code / kind のみ。
- テスト: OFFLINE セッションを WS 経由で最後まで流し、全ログ行に「再生スクリプトの発話本文（8 文字断片）・顧客名・目的・
  カンペ文・トークン・ペアリングコード・偽 API キー」が含まれないことを確認（`offline-e2e.test.ts`、SPEC §16-1 #15）。

## 自動起動（Windows）

- `pnpm autostart:install` は本人のスタートアップフォルダ（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`）に
  `ZEROSYS-SalesCopilot-Server.lnk` を 1 つ置くだけ。管理者権限・タスクスケジューラは使わない（`AIOps-*` 等の既存タスクに触れない）。
- ショートカット → PowerShell（Hidden・最小化）→ `scripts/autostart/start-hidden.ps1`（ASCII のみ）→ node `scripts/autostart-run.mjs`
  （見張り役。二重起動防止・異常終了時は待って再起動・10 分に 5 回落ちたら停止）→ サーバー。待受は従来どおり 127.0.0.1 のみ。
- ログは `USER_DATA_DIR\logs\server.log`（5MB ごとにローテーション・3 世代・0600）と `autostart.log`（起動/終了・終了コードのみ）。
  通常ログと同じく会話本文・トークン・キー・ペアリングコードは出さない。
- APIキーは従来どおり `.env` のみ。自動起動の仕組みはキーを読まない・書かない。

## データ

- `data/sales-copilot.sqlite`（node:sqlite、権限 0600、`data/` は Git 管理外）: 承認済み条件と履歴、セッションで使った条件の版、
  フィードバック（adviceId・評価・種類・promptVersion・rulesVersion・時刻）。学習用に、設定で ON（既定）のときだけ
  評価したカードの欄（今の一手・次に言う一言・今は言わない）・場面タグ・商談目的を保存（顧客名は伏せ字、会話の文字起こしは保存しない）。
  承認済みの営業補正ルールと履歴・版。改善案はモデル出力＝データとして形・長さ・内容（金額・期間・無料・保証・上書き指示・記号）を
  検査してから表示し、承認されるまで助言に使わない。ルールは承認済み条件・出力ルールより優先しない（プロンプトに明記し、検証層も従来どおり）。
- 会話・助言は既定でメモリのみ。終了後は振り返り用に `SESSION_RETENTION_MS`（既定 10 分）だけ保持して破棄。
- 本人が終了時にエクスポートを選んだ場合のみ `exports/`（Git 管理外、0600）へ JSON と Markdown を書き出す。
  Markdown には機密注意を明記し、会話は文字列としてエスケープする（HTML として扱わない）。
- 削除方法: `data/` と `exports/` を削除すればローカルの保存物はすべて消える。外部 API 事業者側の保持は別途確認が必要。

## 停止

- 一時停止・終了・WS 切断（ウィンドウを閉じた）で、STT 接続（CloseStream→close）・生成要求（AbortSignal）・待機キュー・
  タイマー・再生を停止。以後に届いた音声・ボタンは外部へ送らない（テストで確認: SPEC §16-1 #5）。
- 予算上限到達で新規の STT 送信・LLM 呼び出しを止める（80% で警告）。
- LLM の認証失敗は以後の呼び出しを止め、429 は 10 秒のバックオフ。

## Meet ページ内の取得（ワンタップ接続・2026-11-17 追加）

- 拡張がページに入れるスクリプトは `https://meet.google.com/*` だけ。ほかのサイトには入らない（`check-dist.mjs` で検査）。
- 「接続」を押すまで、ページ内では相手の音声トラックを**記録するだけ**で、音声の処理・送信・マイク取得はしない（「拒否」・× なら何もしない）。
- 音声はページ → content script（MessageChannel）→ offscreen（runtime Port）→ ローカルサーバー（127.0.0.1）の順にだけ流れる。
  ページ（Meet）からローカルサーバーへ直接は接続しない。トークンはページにも content script にも渡さない（offscreen だけが持つ）。
- offscreen は service worker が指定したタブの content script からの Port だけを受け付け、形の違うメッセージ・大きすぎる音声は捨てる。
- ページ内の部品（MAIN world のスクリプト）は Meet の JavaScript と同じ空間で動くため、Meet 自身からは見える。扱うのは Meet が元々持っている
  音声だけで、文字起こし・カンペ・トークン・設定は通らない。
- 一時停止・終了・ウィンドウを閉じる・タブを閉じる／再読み込みで、ページ内のマイクのトラックを止め、AudioContext を閉じる（相手側のトラックは Meet のものなので止めない）。
- 新しい通信メッセージ `session.update { purpose }`（商談目的の変更）は、内容をログに出さない（`purpose` は既に redact 対象）。

## 商談の再接続（切れても終わらせない・2026-11-17）

実商談で、画面共有・タブ／ウィンドウ切替のたびに商談が勝手に終わったため、一時的な切断では終わらせないようにした。
安全の約束（見えない状態で取得を続けない・終了で全部止める）は次のように保つ。

- 終了してよいのは「終了」ボタン・カンペ画面を閉じた（`windows.onRemoved` で即時）・Meet のタブを閉じた（`tabs.onRemoved` で即時）・
  通話から退出した（相手の音声トラックも退出ボタンも無い状態が 8 秒続く）の 4 つ。理由はサーバーのログ `endReason` と終了画面に出す（会話の内容は含まない）。
- カンペ画面の「2 秒ごとのハートビートが 10 秒途切れたら停止」は廃止。隠れたページのタイマーは Chrome に間引かれるため、画面共有・切替で誤って止まっていた。
  代わりにカンペ画面との Port を使う（閉じれば確実に切れる）。Port が全部切れて 20 秒戻らなければ停止（閉じた通知が来なかった場合の保険）。
- サーバーとの WS が切れたら、サーバーは商談を `SESSION_RESUME_GRACE_MS`（既定 60 秒）だけ保持し、その間は STT の接続を閉じて新たな外部送信をしない。
  拡張は 0.5 秒〜5 秒の間隔で再接続し、hello（トークン）→ `session.resume` で同じ商談を続ける。猶予を過ぎたら終了（`endReason=connection_lost`）。
  `session.resume` も hello の認証を通った接続からしか受け付けない。
- Meet のページとの Port が切れたら、拡張は 45 秒だけ同じタブからの再接続を待つ（他のタブからは受け付けない）。その間は音声を送らない。
- 一時停止・終了の動作は変わらない（止めたら外部送信なし）。
